Predicting how risky a portfolio will be next month

Part 1

Theory you need first

No finance or ML background assumed. Each concept shows the idea, the formula, a worked number, and where it appears in this project.

Suggested study order

  • Day 1, finance basics. Returns, volatility, drawdown, VaR (sections below). You should be able to compute each by hand for a 5-day example.
  • Day 2, portfolios and baselines. Correlation and diversification, then EWMA, GARCH and HAR. These are the "traditional" side of the comparison.
  • Day 3, ML models. Random Forest, XGBoost, LSTM, and why time-series data needs special validation.
  • Day 4, evaluation and results. The metrics guide, then Part 2 (the project), then the self-test and likely questions.

One idea ties everything together: risk is predictable because it persists. Calm weeks tend to be followed by calm weeks, and stormy weeks by stormy weeks. Every model here exploits that, with different amounts of machinery.

Theory 1

Returns: the raw material

A return is the percentage change in price over a period. Almost every risk number is computed from a series of daily returns, not from prices.

simple return r_t = P_t / P_(t-1) - 1 portfolio r_p,t = w1*r1,t + w2*r2,t + ... + wn*rn,t (weights sum to 1) growth of 100 W_t = 100 * (1+r_1)(1+r_2)...(1+r_t) (compounding)
Example. A portfolio with 60% in stock A and 40% in gold. On a day A rises 2% and gold falls 1%, the portfolio return is 0.6 × 2% + 0.4 × (−1%) = 0.8%.

In this project: 45 tickers give 45 daily return series. A "portfolio" is just a set of weights, and its return series is built exactly as above, rebalanced to the same weights every day (a simplifying assumption). Adjusted close prices are used so dividends and splits do not look like returns.

Annualizing: there are about 252 trading days a year. A daily number is scaled to a yearly one by multiplying a daily volatility by √252 ≈ 15.9. That is why you see "annualized volatility" everywhere.
Theory 2

Volatility: how bumpy the ride is

Volatility is the standard deviation of returns. A high value means returns swing widely, so the portfolio's value is less predictable. It is the most common single measure of risk.

daily vol s = standard deviation of the last N daily returns annualized vol = s * sqrt(252) realized vol = vol measured on returns that already happened
Example. Daily returns with a standard deviation of 1% give an annualized volatility of 1% × 15.9 = 15.9%. Roughly speaking, a year's return would typically land within ±16% of its average, about two times out of three.

Why volatility can be forecast

  • Clustering. Big moves follow big moves and quiet days follow quiet days. This is the single most reliable pattern in market data.
  • Mean reversion. Very high volatility drifts back toward a long-run level, and very low volatility creeps up.
  • Leverage effect. Falling prices tend to raise volatility more than rising prices do.

Returns themselves are close to unpredictable. Volatility is not. That asymmetry is why this project predicts risk, not prices.

In this project: the target vol_fwd is the realized volatility over the next 21 trading days (about one month), annualized. The input vol_21 is the same measure over the past 21 days. The naive forecast simply says "next month's volatility equals last month's".

Theory 3

Drawdown: how far you fall from the top

Volatility treats gains and losses alike. Investors care more about losses, and a drawdown measures the loss from the highest point so far.

wealth path W_t (value of the portfolio over time) running peak M_t = highest W seen up to t drawdown D_t = W_t / M_t - 1 (zero or negative) max drawdown MDD = the most negative D_t in the window
Example. A portfolio goes 100, 120, 90, 110. The peak reaches 120 and the low is 90, so the maximum drawdown is 90 / 120 − 1 = −25%, even though it ends above where it started.

In this project: the target dd_flag is 1 if the maximum drawdown over the next 21 days reaches 5% or worse, else 0. The starting value counts as the first peak. The model outputs a probability of that event. About a third of all rows are 1, because 5% is not a rare fall for equity portfolios in a month.

Theory 4

Value at Risk (VaR): a loss that should be rare

The 95% one-day VaR answers: "On a normal day, what loss will I stay within 95% of the time?" Equivalently, it is the loss that should be exceeded on only 1 day in 20. It is a quantile of the return distribution, specifically the 5th percentile.

historical VaR = the 5th percentile of the last 250 daily returns parametric VaR = mean - 1.645 * s (assumes returns are normal) exceedance = a day when the actual return is worse than the VaR a good 95% VaR -> exceedances on about 5% of days
Example. Daily volatility 1%, mean 0. Parametric VaR = −1.645%. The model says: only about 1 day in 20 should lose more than 1.65%.

How to judge a VaR model

  • Exceedance rate. Count the days the loss beat the VaR. Too many means the model understates risk (dangerous). Too few means it is too cautious.
  • Kupiec test. A statistical test of whether the exceedance rate differs from 5%. A small p-value (below 0.05) means "not calibrated". With 100 days, 5 exceedances is expected and 10 gives p ≈ 0.04, a rejection.
  • Pinball loss. A score that rewards a good quantile estimate (explained in the metrics section).
Limits of VaR: it says nothing about how bad the loss is once the line is crossed. Banks therefore also use Expected Shortfall (the average loss beyond VaR). This project covers VaR only, which matches the synopsis.
Theory 5

Other features the models read

Sharpe ratio

(avg daily excess return) / (daily vol) * sqrt(252)

Return earned per unit of volatility. "Excess" means above the risk-free rate, set to 6% a year for India. Higher is better.

Sortino ratio

same, but divide by the volatility of losses only

Like Sharpe but only downside swings count as risk, so upside volatility is not punished.

Momentum

return over the last 21 / 63 / 126 days

Recent trend. Strong falls often come with rising risk.

Skew and kurtosis

shape of the return distribution

Negative skew means big losses are more likely than equally big gains. High kurtosis means fat tails: extreme days are more common than a normal curve predicts.

Beta and correlation to market

beta = cov(r_p, r_m) / var(r_m)

How strongly the portfolio moves with the NIFTY index. Beta 1.2 means it tends to move 1.2% for every 1% the market moves.

VIX

India VIX level and daily change

The market's own expectation of near-term volatility, implied by option prices. A strong signal of fear.

Why three windows (21, 63, 126 days)? They are roughly one month, one quarter and half a year. Short windows react fast but are noisy. Long windows are stable but slow. Giving the model all three lets it judge whether recent behaviour is unusual.

Theory 6

Correlation and diversification

Holding several assets lowers risk only when they do not all move together. Correlation ranges from −1 (opposite) through 0 (unrelated) to +1 (identical moves).

two assets: vol_p^2 = w1^2*s1^2 + w2^2*s2^2 + 2*w1*w2*rho*s1*s2 many assets: vol_p^2 = w' * Sigma * w (Sigma = covariance matrix)
Example. Two assets, each with 20% volatility, held 50/50. If correlation is 1, portfolio volatility is 20% (no benefit). At 0.5 it falls to 17.3%. At 0 it falls to 14.1%. Diversification is free risk reduction.

The catch. In a market crash, correlations jump toward 1 and diversification disappears just when it is needed. This is exactly the "non-linear and dynamic correlations" the synopsis mentions, and the reason the models get the mean pairwise correlation of the holdings as a feature.

Ledoit-Wolf (a baseline here) forecasts portfolio volatility from this formula. Estimating a covariance matrix from limited data is noisy, so it "shrinks" the noisy estimate toward a simpler, more stable one, which is more reliable out of sample.

Theory 7

How each model works

Traditional models

EWMA

var_t = 0.94*var_(t-1) + 0.06*r_t^2

Today's variance is mostly yesterday's, nudged by the latest squared return. Recent days weigh more than old ones. No parameters to fit (0.94 is the standard RiskMetrics value).

GARCH(1,1)

var_t = w + a*r_(t-1)^2 + b*var_(t-1)

Like EWMA but it also pulls variance back toward a long-run average (w / (1 − a − b)). The parameters are estimated from data. It is the classic academic benchmark and is fit separately for each portfolio.

HAR-style regression

log(future vol) = c + b1*log(vol_21) + b2*log(vol_63) + b3*log(vol_126)

A plain linear regression on short, medium and long past volatility. Simple, and surprisingly hard to beat.

The traditional models only look at the portfolio's own past returns. They cannot use the VIX, macro data or cross-asset correlation. That is the opening for ML. The project also uses GJR-GARCH (GARCH where bad news raises volatility more than good news, with fat-tailed errors), filtered historical simulation and a simulated-drawdown model, described in Part 2.

Machine learning models

Random Forest

Builds many decision trees. Each tree asks a chain of yes/no questions about the features ("is 21-day vol above 18%? is the VIX rising?") and ends in a prediction. Each tree sees a random part of the data and features, and the forest averages all trees. Averaging cancels individual errors. Weakness: it can memorize the training period unless trees are kept small.

XGBoost

Also trees, but built one after another. Each new small tree is trained to fix the mistakes the earlier trees made (gradient boosting). A learning rate controls how big each correction is. Early stopping halts adding trees once the validation error stops improving. Usually stronger than a Random Forest on tabular data, but sensitive to its settings.

LSTM (neural network)

A recurrent network reads a sequence of days in order, here the last 21, and keeps a hidden memory vector that it updates each day through learned "gates" (what to remember, what to forget, what to output). Its last memory state feeds a small output layer. It learns patterns from the raw sequence without hand-made features. It needs more data and care, and is trained by gradient descent with early stopping.

Quantile regression and probabilities

  • Predicting a quantile. For VaR, XGBoost and the LSTM are trained with the pinball loss, which penalizes under- and over-estimates unequally so the best answer is the 5th percentile rather than the average.
  • Predicting a probability. For drawdown, the models output a number between 0 and 1 and are trained with log-loss, which punishes confident wrong answers heavily.
  • Predicting the change in volatility. The models predict log(future vol ÷ current vol), then convert back. This stops them from just copying today's value.
Theory 8

Machine learning on time series: where students go wrong

Ordinary ML advice (shuffle, split randomly, cross-validate) gives inflated, meaningless scores on time series. These are the traps, and the rule this project uses against each.

TrapWhy it cheatsRule used here
Look-ahead leakageA feature uses information from after the prediction date, so the model "knows" the future.Features use data up to day t only. Targets use days t+1 to t+21 only. Tests change future data and check nothing earlier moves.
Random train/test splitNeighbouring days are almost identical, so a random split puts near-copies of test rows in training.Walk-forward: train on the past, test on the next year, then move forward.
Overlapping targetsA target looks 21 days ahead, so a training row from just before the test period contains test-period information.A 21-day purge gap between the end of training and the start of testing.
Fitting scalers on all dataNormalizing with future averages leaks the future scale.Scalers are fit on the training period only, then applied to later data.
Macro data published lateCPI for January is not known on January 31.Each macro series is shifted by its real publication delay (CPI by 45 days).
Weak baselinesBeating a bad benchmark proves nothing.Strong baselines: HAR, GARCH, GJR-GARCH, Ledoit-Wolf, EWMA, and Round 4 gives the ML models the same HAR/GARCH information.
Tuning on the test setPicking settings that look best on the test years overstates performance.Hyperparameters were set once by reasoning, never tuned on test years, and the Round 4 choices were pre-registered before any result existed.

Walk-forward in one picture. Fold 1 trains on data from 2010 to late November 2019 and tests on 2020. Fold 2 trains up to late November 2020 and tests on 2021. And so on, with the last fold testing from January 2025 into 2026. The training window expands each time, mimicking how a real forecaster would have worked.

Non-stationarity. Markets change regime (calm bull market, 2020 crash, rate-hike year). A model trained on one regime can fail in another. That is why results are also split into calm and stress periods.

Part 2

The project and its final (Round 4) results

What was built, how it was tested, and what it found. Every number on this page was read from the project's result files.

The answer in one screen

What we found

ML is competitive with strong traditional models. It is not better than them. On a one-month horizon with daily data, the best single volatility model is a plain GJR-GARCH. The ML models beat the naive "next month equals last month" forecast with statistical support, but no ML model beats the best traditional model in a significant way. We report that as the finding.

Volatility

Ranked by QLIKE (our pre-registered main loss), GJR-GARCH is first (0.281), then the XGBoost-HAR-GARCH combination (0.298), the LSTM (0.299) and XGBoost (0.306). By RMSE the combination is first (0.0697). The ranking depends on the loss.

Drawdown probability

A GARCH-based simulation with a logistic correction has the best Brier score (0.2046). RF (0.2061) and the LSTM (0.2062) are close behind. Its edge does not survive the multiple-testing correction.

95% VaR

Pinball loss is about 0.0014 for every model. GJR is lowest at 0.001367. Raw exceedance rates drift away from 5% in some years for every model. Online calibration brings the average to 4.6% to 4.9%.

Round 3 to Round 4

Giving the ML models the HAR and GARCH forecasts as extra inputs improved most of their metrics. None of the 8 tests of that improvement is significant.

The problem

Three questions about the next 21 trading days

How volatile?

Annualized realized volatility of the portfolio over the next 21 days. Regression.

target: vol_fwd

How likely is a 5% drop?

Probability that the worst peak-to-trough fall inside the window reaches 5% or more. Classification with a probability output.

target: dd_flag

How bad is a bad day?

The 95% one-day Value at Risk: the loss that should be exceeded on only 1 day in 20. Quantile regression.

target: next-day return, 5% quantile
Intuitive example. A portfolio is 40% IT stocks, 40% banks and 20% gold. We ask three things on a given date. (1) Will the portfolio swing like a 12%-a-year investment or a 25%-a-year one over the next month? (2) What is the chance it falls at least 5% from its peak at some point in that month? (3) What loss should be exceeded on only about one trading day in twenty? The first is a size, the second a probability, the third a loss level.

Why bother. Classic tools (historical VaR, standard deviation, GARCH) assume the recent past describes the near future. The project asks whether ML, given richer inputs, predicts risk better, and answers with a fair, pre-planned comparison. The synopsis commits to Random Forest, XGBoost and an LSTM against traditional models, judged by RMSE, MAE and directional accuracy, with a Streamlit dashboard. All of that is delivered.

Data and setup

45 NSE tickers, 2010 to 2026

Universe

40 NIFTY large caps plus 5 index, sector and gold ETFs (NIFTYBEES, JUNIORBEES, BANKBEES, PSUBNKBEES, GOLDBEES). Adjusted close prices from Yahoo Finance, so dividends and splits do not look like returns.

Macro inputs

India VIX, plus US 10-year yield, USD/INR, Brent crude, US fed funds rate and US CPI inflation. Each is lagged by its real publication delay (CPI by 45 days, USD/INR and Brent by 10 days) and enters as a change, because levels let trees memorise calendar regimes.

Synthetic portfolios

400 random portfolios of 3 to 15 assets with random (Dirichlet) weights, sampled on every 5th trading day. The model sees how a portfolio has behaved, not which stocks it holds, so one model can score any user portfolio. 80 portfolios are never used for training and are scored separately.

Why synthetic portfolios. One real portfolio would give one return series and nothing to generalize from. Many random ones teach the model how past risk, correlation and market conditions relate to future risk, for any mix of the 45 tickers. The catch is that all portfolios share the same market days, so they add less independent information than the number 400 suggests.

Data quality. Yahoo had some bad prints. Any daily move above 50% is treated as a data error, set to zero and logged in reports/return_jumps.csv. There is no bond asset, because Indian gilt ETFs do not have history back to 2010, so gold is the only diversifier.

Why the numbers can be trusted

Rules that prevent cheating

No look-ahead

Features at day t use data up to t. Targets use days t+1 to t+21. Tests change the future and check that nothing at or before t moves.

Walk-forward folds

6 expanding-window folds. Test periods start in 2020, 2021, 2022, 2023, 2024 and 2025 (the last runs into 2026). Never a random split.

21-day purge

Training rows end 21 days before the test starts, because a training target looks 21 days ahead and would otherwise overlap the test period.

Same yardstick

Every model, including the baselines, is scored on identical rows by one evaluation file. Scalers are fit on training data only. Seed is 42.

Held-out portfolios

80 portfolios are excluded from every training row, so we can check the models on portfolios they have never seen.

Pre-registration

The Round 4 choices were written down in code (src/models/prereg.py) before any Round 4 number existed. A test pins them so they cannot drift quietly.

194 automated tests cover this, including hand-computed targets and metrics, perturbation tests for leakage (including the backtest view), fold purge checks, a check that the app computes exactly the features used in training, and forecast-log scoring.

Contenders

The models in plain language

Traditional models

Naive

Next month's volatility equals the last 21 days. The floor any model should beat.

EWMA

A moving estimate where recent days count more than old ones. No fitted parameters.

Ledoit-Wolf

Estimates how all the holdings move together, with a stabilizing "shrinkage", then works out the portfolio's volatility from that.

HAR

A linear regression of future log volatility on 21, 63 and 126-day past volatility.

GARCH(1,1)

Variance depends on yesterday's shock and yesterday's variance, and drifts back to a long-run level.

GJR-GARCH(1,1) with t errors

GARCH that lets bad news raise volatility more than good news, and allows fat-tailed returns. This turned out to be the best single volatility model.

Filtered historical simulation (FHS)

A VaR method. Use GARCH to remove the volatility pattern, take the 5% quantile of the leftover shocks, then scale back to today's volatility.

Simulated drawdown

For drawdown probability: simulate 2,000 GARCH return paths per portfolio and date, and count how often one falls 5% in 21 days. A second version adds a logistic recalibration.

Historical and parametric VaR

Historical takes the 5th percentile of recent returns. Parametric assumes normal returns. A base-rate model always predicts the training frequency of a 5% drawdown.

Combinations

Equal-weight averages of forecasts. HAR+GARCH, and HAR+GARCH+XGBoost. No weights are estimated.

Machine learning models

Random Forest

Many decision trees, averaged. Predicts volatility and drawdown probability. No quantile loss, so no VaR.

XGBoost

Trees built one after another, each fixing the previous errors. Predicts all three targets. VaR uses a quantile (pinball) objective. Up to 600 rounds per head, keeping the validation-curve minimum.

LSTM (PyTorch)

One single-layer network reading the last 21 days, with three outputs (volatility, drawdown, VaR). Each head keeps the weights of its own best validation epoch, then is refit on all training rows.

All three ML models also receive the HAR and GARCH forecasts as inputs (see above). Hyperparameters were set once by reasoning and not tuned.

Two things the combinations show. First, the best RMSE overall (0.0697) comes from averaging XGBoost with HAR and GARCH, which says ML and econometrics complement each other more than they compete. Second, those combinations were chosen after the Round 3 ranks were known. We say so, and we do not count them as the "best baseline" in any test.

Calibrating VaR

An online correction nudges every VaR forecast, baselines included. A model that has been missing too often gets deeper, one that is too cautious gets shallower. The step size (0.25) was fixed by reasoning before the run, and the held-out portfolios never feed it. It fixes the average miss rate over time. It gives no guarantee for a single year or market regime.

How we evaluate

Metrics, tests and why we chose them

RMSE, MAE, directional accuracy

The metrics promised in the synopsis. Directional accuracy asks whether the forecast moved the same way as actual volatility relative to today. We report all three.

QLIKE (main ranking loss)

An error score for volatility that is robust to noise in the realized-volatility measure, and treats under-forecasting as worse than over-forecasting. Realized volatility over 21 days is a noisy yardstick, so a robust loss gives a more trustworthy ranking than RMSE. Chosen in advance as the main ranking loss.

Brier, log-loss, AUC

For drawdown probabilities. Brier and log-loss judge the probability itself. AUC judges only whether risky periods are ranked above calm ones.

Pinball, exceedance, Kupiec

For VaR. Pinball is the quantile loss. Exceedance is how often losses beat the VaR line (target 5%). Kupiec tests whether that rate is 5%, but treats all portfolio-days as independent, so it over-rejects.

Diebold-Mariano with Holm

Is a loss gap between two models bigger than chance? The test works on date-level average losses (about 330 dates), not on the 400 portfolios, because portfolios share dates. Holm correction adjusts for running many tests at once.

Model confidence set (90%)

The group of models the data cannot rule out as the best. A model outside the set is clearly worse.

Reading "significant". With roughly 330 test dates and six test years, differences between good models are small compared with how much results move from year to year. Mean ± standard deviation across folds is reported everywhere, and the standard deviations are large. A gap smaller than the spread is not a win.

Pre-registration. Before the Round 4 run we wrote down the models, losses, tests and the way ties are handled. That stops us from picking the metric that makes our favourite model look best after the fact. The choices that were made after seeing Round 3 results (the two combinations) are marked as such.

For ranking risky periods (ROC-AUC), GJR is best at 0.644, then the XGBoost-HAR-GARCH combination 0.634, LSTM 0.632, GARCH 0.632, XGBoost 0.616 and Random Forest 0.607. Held-out portfolios: simulated drawdown 0.2023, Random Forest 0.2035.

Be precise about it

What we can claim and what we cannot

We can claim

  • ML is competitive with strong traditional models at a 21-day horizon.
  • XGBoost and the LSTM beat naive volatility on QLIKE, significant after Holm correction (p 0.015 and 0.008).
  • The evaluation is leak-free by design: time-based folds, a 21-day purge, scalers fit on training data, tests, pre-registered choices.
  • Adding HAR and GARCH forecasts as inputs improved most ML metrics.
  • The simulated-drawdown model gives the best-calibrated drawdown probabilities.
  • A simple online calibration brings average VaR exceedance to 4.6% to 4.9%.
  • The rankings change with the loss, and this is shown openly.

We cannot claim

  • That ML beats GARCH, GJR or HAR. No test supports it.
  • That the Round 4 improvement over Round 3 is real. None of the 8 tests is significant.
  • That the simulated-drawdown edge is real. It does not survive Holm correction.
  • That any model gives a calibrated VaR in every year or regime.
  • That regime patterns (traditional better in stress, ML in calm) hold. No test is significant.
  • That results generalize beyond Indian large caps, 2010 to 2026, or to real trading.
  • That the deployed app models are better than the walk-forward models. They are for demonstration.
Be upfront about these

Limitations

  • Small effective sample. Only about 190 independent 21-day periods exist since 2010, and portfolios share market days. Fold-to-fold variance is large and 400 portfolios add compute, not much independent information.
  • Low statistical power. About 330 test dates cannot separate the leading models. The DM, confidence-set and coverage tests also assume stationary loss differences, which expanding windows do not guarantee.
  • No tuning, one seed. Hyperparameters were set once by reasoning. The Round 4 setup has not been re-seeded. For the Round 3 setup the LSTM moved noticeably across seeds (vol RMSE 0.070 to 0.075, Brier 0.208 to 0.217) while XGBoost and RF barely moved.
  • Deployed models. The deployed LSTM's volatility and drawdown heads stop at epoch 1. The app's models are for demonstration, and all reported numbers come from the walk-forward fold models.
  • Test of independence in VaR. The pre-registered date-level DQ test rejects too often in simulation (12% to 40% at a nominal 5%), so its results are descriptive only. Pooled Kupiec tests overstate sample size, so the date-clustered test is the better guide.
  • Data. Yahoo data is delayed and occasionally wrong (bad prints are zeroed and logged). Today's large caps imply survivorship bias. There is no bond asset. Only US macro series are used. Portfolios are rebalanced daily.
  • Forecast log. Scores from a handful of saved forecasts are anecdotes, not evidence.
  • Not investment advice. Built for study and presentation.

Prepare for these

Likely examiner questions

Why doesn't ML win?

Volatility is largely explained by recent volatility, which HAR and GARCH use directly and efficiently. Published work finds HAR and GARCH-type models are hard to beat at a one-month horizon with daily data. With about 190 independent periods there is little room to learn more. ML does add something (the XGBoost combination has the best RMSE), and it beats naive volatility significantly, but it does not beat the best traditional model. Papers claiming 90%+ accuracy usually predict prices, which is a different task.

How did you prevent leakage?

Features at day t use data up to t only, and targets use t+1 to t+21 only. Folds are time-based with a 21-day purge so overlapping targets cannot cross into the test period. Scalers are fit on training rows only, macro series are lagged by their publication delay, and the HAR and GARCH inputs are re-estimated once a year on earlier data only. Tests change the future and confirm nothing at or before t moves.

Why synthetic portfolios?

So one model serves any user portfolio. The inputs describe the portfolio's own behaviour (volatility, drawdown, correlation), not which stocks it holds. The limitation is that portfolios share the same market days, so 400 portfolios do not mean 400 independent samples. We also scored 80 held-out portfolios, and the picture was the same.

Is six test years enough?

No, not to separate close models. There are about 190 independent 21-day periods since 2010 and about 330 test dates. That is why the confidence set keeps almost every model, and why we report which gaps are significant instead of ranking by the third decimal. It is enough to show ML is competitive and to show that a big ML advantage does not exist in this data.

Why QLIKE?

The realized volatility we compare against is a noisy measurement. QLIKE (and MSE on variance) still rank models correctly under that noise, while RMSE on volatility can favour the wrong model. We chose it as the main ranking loss before the run and still report RMSE, MAE and directional accuracy, because the synopsis asks for them. The ranking does differ: the combination wins on RMSE, GJR on QLIKE.

Are the combinations a form of cheating?

They were picked after we had seen the Round 3 ranks, and we disclose that. They are plain equal-weight averages with nothing fitted. They are also excluded from the pool of "best baseline" in the tests, so they do not make the comparison easier or harder for ML.

Why is the drawdown base rate about a third?

Because the window is 21 days and the threshold is 5% peak-to-trough, which equity portfolios hit often. In the test years about 32% of rows had such a drawdown. All models are judged against that base rate (Brier 0.2199).

The simulated drawdown model has the best Brier. Is it the winner?

It is first in the table and best calibrated, but its edge over GARCH (raw p 0.034) and over the base rate (raw p 0.013) does not survive Holm correction (0.101 and 0.052). We report it as best on the table and not demonstrably better.

Does the VaR work?

Pinball loss is about 0.0014 for every model. Raw yearly exceedance rates swing between about 2% and 11% for all of them. The pooled Kupiec test rejects often but is overpowered. The date-clustered test does not reject the average rate for any model. Online calibration brings the average to 4.6% to 4.9%, with no promise for a single year or regime.

Why did you not tune the models or use more seeds?

Tuning on the test years would inflate performance, and tuning inside training would multiply the number of choices. We set values once by reasoning, wrote down the choices before the run, and report what came out. Re-seeding the Round 4 setup is a sensible next step. For the Round 3 setup, seeds 1 and 2 moved the LSTM noticeably and XGBoost and RF barely.

Does the app retrain when I click?

No. It loads saved models, builds the same features from cached prices and runs predictions. Past dates in the Backtest view use the walk-forward models trained only on earlier data. The deployed models are for demonstration.

Can this be used for trading?

No. It is a study project with limits listed above, including survivorship bias, no bonds and a short sample. It is not investment advice.

What would you do next?

Re-run the Round 4 ML setup with several seeds, tune hyperparameters inside the training window, add more assets including bonds if history allows, and test a longer sample. These are ideas, not results.

Check yourself

Self-test: can you explain these?

Answer aloud first, then open the answer.

1. A portfolio has 1.2% daily volatility. What is it annualized?

1.2% × √252 ≈ 1.2% × 15.87 ≈ 19.0%.

2. A portfolio goes 100, 130, 117, 125. What is the maximum drawdown?

The peak is 130 and the low after it is 117, so 117 / 130 − 1 = −10%. The later rise to 125 does not erase it.

3. Over 250 days a 95% VaR model has 14 exceedances. Is that a problem?

Expected is 12.5 (5% of 250), so 14 is close and probably passes the Kupiec test. If it had 25, the model would clearly understate risk. Fewer than about 6 would mean it is too cautious.

4. Why does diversification fail in a crash?

Correlations rise toward 1 in a crash, so assets fall together. The formula for portfolio volatility depends on correlation, so the benefit vanishes when correlation approaches 1.

5. Why not predict tomorrow's price instead of risk?

Returns are close to unpredictable, while volatility clusters and persists. Risk can be forecast with measurable accuracy, which is what the synopsis promises.

6. Why can't we split the data randomly into train and test?

Adjacent days are nearly identical, so random splitting puts near-copies of test rows in training and also lets the model learn from the future. Walk-forward testing mimics real use.

7. What does the 21-day gap protect against?

A training row's target covers the next 21 days. Without the gap, the last training rows would contain returns from inside the test period.

8. What is the difference between Random Forest and XGBoost?

A forest builds many independent trees and averages them. XGBoost builds trees one after another, each correcting the previous ones' errors.

9. A model has Brier score 0.22 for drawdown. Is it good?

Not by itself. Always guessing the base rate scores 0.2199. A useful model must score clearly below that. In Round 4 the simulated-drawdown model (0.2046), Random Forest (0.2061), LSTM (0.2062) and XGBoost (0.2101) do, but the gaps are small relative to the year-to-year spread.

10. Why predict log(future vol ÷ current vol) instead of future vol?

Volatility persists, so a model asked for the level mostly copies the current value and looks accurate without learning anything. Predicting the change forces it to find real information.

11. A model beats naive with raw p = 0.001 but we quote Holm p = 0.015. Why?

We ran several tests at once. Each extra test raises the chance of a false alarm, so Holm correction raises the p-values to keep the overall error rate controlled. 0.015 is still below 0.05, so the result stands.

12. Model A has RMSE 0.0697 and model B has QLIKE 0.281. Who is better?

It depends on the loss. The two losses can disagree, which is why we picked QLIKE as the main one before running anything. Neither gap is statistically significant against the other.

Reference

Glossary

Return
Percentage change in price over a period.
Volatility
Standard deviation of returns, usually annualized.
Realized vs implied
Realized is measured from actual past returns. Implied (VIX) is the market's expectation from option prices.
Drawdown
Fall from the highest value so far. Max drawdown is the worst such fall in a window.
VaR (95%, 1-day)
Loss that should be exceeded on only 5% of days. The 5th percentile of returns.
Exceedance
A day when the loss was worse than the VaR.
Kupiec test
Statistical test that the exceedance rate equals the target (5%).
Sharpe / Sortino
Excess return per unit of total volatility / of downside volatility.
Beta
Sensitivity of the portfolio to the market index.
Covariance matrix
Table of how every pair of assets moves together. Drives portfolio volatility.
Shrinkage
Pulling a noisy estimate toward a simpler, steadier one (Ledoit-Wolf).
EWMA
Exponentially weighted moving average: recent observations count more.
GARCH
Model where today's variance depends on yesterday's shock and yesterday's variance.
HAR
Regression of future volatility on short, medium and long past volatility.
Feature
An input column the model learns from (for example 21-day volatility).
Target
The quantity the model predicts (future volatility, drawdown flag, next-day return).
Look-ahead leakage
Using information that would not have been known at prediction time.
Walk-forward
Training on the past and testing on the following period, then rolling forward.
Purge gap
Days removed between train and test so overlapping targets cannot leak.
Decision tree
A chain of yes/no questions on features that ends in a prediction.
Boosting / bagging
Boosting builds trees in sequence to fix errors. Bagging averages independent trees.
LSTM
Recurrent neural network with gated memory, suited to sequences.
Early stopping
Stop training when validation error stops improving, to avoid memorizing.
Overfitting
Learning the quirks of the training period so well that new data is predicted poorly.
Hyperparameter
A setting chosen before training (tree depth, learning rate), as opposed to values the model learns.
Pinball loss
Asymmetric error score used to train and judge quantile forecasts.
Brier score / log-loss
Scores for probability forecasts. Lower is better.
ROC-AUC
Ability to rank events above non-events. 0.5 is chance.
Base rate (climatology)
The overall frequency of an event, used as the "no skill" forecast.
QLIKE
Volatility error score that is robust to a noisy realized-volatility yardstick. The main ranking loss here.
Diebold-Mariano test
Tests whether two models' forecast losses differ by more than chance.
Holm correction
Raises p-values when many tests are run together, so lucky results are not mistaken for real ones.
Model confidence set
The group of models the data cannot rule out as the best.
GJR-GARCH
GARCH where falls raise volatility more than rises, here with fat-tailed (Student-t) errors.
FHS
Filtered historical simulation: a VaR method that uses GARCH-standardized past shocks.
Pre-registration
Writing down models, metrics and tests before any result exists, so they cannot be chosen after the fact.
Calibration (VaR)
An online correction that deepens or relaxes VaR forecasts so the miss rate stays near 5% on average.
Combination forecast
An equal-weight average of several models' forecasts.
Synthetic portfolio
A randomly generated set of tickers and weights used to train a model that generalizes.
Survivorship bias
Using only companies that exist today, which hides the ones that failed or left the index.
